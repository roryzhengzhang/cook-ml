The 7B reference model used across this series is 32 copies of the same unit stacked on top of each other, and almost everything about its size, cost and training behavior comes from that one unit, called a block. Each token travels up the stack as a list of numbers, and every block reads that list and adds a correction to it instead of rewriting it. Questions about model size, training cost and stability mostly come down to how the blocks are wired, which is a separate matter from what the model is trained to predict.

A network built from such blocks is a **transformer**. This chapter covers the **decoder-only** kind, which reads text left to right and predicts the next token. GPT, Llama, Qwen and Mistral are all built this way, so every block, count and cost below is for a decoder. The other two families, encoders and encoder-decoders, appear only in the last section, which compares them.

Each block holds two parts, and both follow the same routine. Attention lets a token pull information from earlier tokens, and the **feed-forward network** transforms each token on its own. Each part reads a rescaled copy of the running list, computes something, and adds the result back. Once that routine is clear, the model's anatomy reduces to counting. Counting the matrices gives the parameters, doubling that gives the arithmetic per token, and swapping one part for several copies gives a mixture of experts.

![Residual stream](/images/llm-fundamentals/15d-residual-stream.png)

The figure carries the main idea of the whole chapter. The stream keeps the same width from the embedding at the bottom to the output head at the top, and no block ever overwrites it. Because the blocks only add, the final vector is the embedding plus 64 sublayer contributions, and a gradient can reach any block straight down the identity path.

The sections take that stack apart one piece at a time and then rebuild it. The residual stream comes first, since every other part writes into it, followed by the normalization that keeps it at a steady scale and the question of where in the block that normalization sits. The feed-forward network and its gated SwiGLU version come next. They hold most of the parameters. With those pieces in hand, a full decoder block can be assembled, along with the output head that turns the final vector into next-token scores.

A finished model leaves two more questions open, namely what it costs and what else it could have been. Counting parameters and FLOPs per token answers the first. The second is answered by a mixture of experts, which grows the parameter count without growing the cost per token, and by a comparison of encoders, decoders and encoder-decoders.

## The residual stream

Any deep stack has to answer one design question, which is whether each layer replaces its input or edits it. If every layer recomputes its output from scratch, errors compound with depth and information from the embedding and early layers can fade. A **residual connection** takes the editing route: a layer's output is added to its input instead of replacing it. The **residual stream** is the running vector those additions build up, one per token, from the **embedding** (the learned starting vector looked up for the token, covered in [Tokenization](/tutorials/llm-fundamentals/tokenization-and-embeddings/)) to the final layer. It was introduced for image networks by [ResNet](https://arxiv.org/abs/1512.03385) and is used in every transformer since the original [Transformer](https://arxiv.org/abs/1706.03762).

Each block contains two **sublayers**, attention and then the feed-forward network. Treating a whole block as one update for now, block $\ell$ changes the stream by $x_{\ell} = x_{\ell-1} + F_\ell(x_{\ell-1})$, where $x_{\ell-1}$ is the stream entering, $F_\ell$ is what block $\ell$ computes from it, and $x_\ell$ is the stream leaving. The [decoder block](#the-decoder-block) section shows that a block actually makes this addition twice, once per sublayer. Unrolling the sum over all $L$ blocks gives $x_L = x_0 + F_1 + F_2 + \dots + F_L$, with each $F_\ell$ evaluated on the stream it read, so the final vector is literally the embedding plus every contribution.

The same additive structure is what keeps training possible at depth. The loss is a single number measuring how wrong the model's predictions are. A **gradient** is the signal saying how much the loss would change if a parameter moved, and training sends it backward from the output through every layer. In a plain stack each layer multiplies the gradient by its own local slope, so 32 layers that each scale it by 0.5 shrink it to $0.5^{32} \approx 2.3 \times 10^{-10}$, which is the **vanishing gradient** problem. With residual connections the derivative of $x_L$ with respect to any $x_\ell$ always contains a term equal to 1 from the identity path, so block 1 receives the top-level gradient undiminished plus whatever the blocks above add to it. Interpretability work often reads the stream as a shared workspace that attention moves information into and the feed-forward network writes facts into, a view developed in Anthropic's [transformer circuits framework](https://transformer-circuits.pub/2021/framework/index.html).

## Layer normalization and RMSNorm

Adding contributions block after block lets the stream's numbers drift in size, and a sublayer that sees inputs ten times larger than the ones it learned on will behave differently. **Normalization** is a rescaling step that prevents this: it takes a vector and returns a version with a standard size, so the next layer always sees inputs on a predictable scale. **Layer normalization**, or LayerNorm, from [Ba et al.](https://arxiv.org/abs/1607.06450), works within one token's vector. It subtracts the mean of the coordinates, divides by their standard deviation, then applies a learned scale and shift:

$$
\operatorname{LayerNorm}(x) = g \odot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + b.
$$

Here $\mu$ is the average of the $d$ coordinates, $\sigma$ is their standard deviation, $\epsilon$ is a tiny constant such as $10^{-5}$ that keeps the denominator above zero, and $\odot$ multiplies coordinate by coordinate. The **gain** $g$ is a learned scale per coordinate and the offset $b$ is a learned shift per coordinate, which together let the model undo the standardization where that helps.

**RMSNorm**, from [Zhang and Sennrich](https://arxiv.org/abs/1910.07467), skips the mean subtraction and the offset, and divides by the root mean square $\operatorname{RMS}(x)$ instead, the square root of the average squared coordinate $x_i$, and then multiplies by the same learned gain $g$:

$$
\operatorname{RMSNorm}(x) = g \odot \frac{x}{\operatorname{RMS}(x)}, \qquad \operatorname{RMS}(x) = \sqrt{\tfrac{1}{d}\textstyle\sum_i x_i^2 + \epsilon}.
$$

## Pre-norm and post-norm placement

Once a block has a normalization step, the remaining question is where to put it, either on the way into each sublayer or after the addition. **Post-norm**, used in the original Transformer, normalizes after the addition, $x_\ell = \operatorname{Norm}(x_{\ell-1} + F_\ell(x_{\ell-1}))$. **Pre-norm**, used from GPT-2 onward, normalizes only the copy the sublayer reads, $x_\ell = x_{\ell-1} + F_\ell(\operatorname{Norm}(x_{\ell-1}))$, and leaves the stream itself untouched. In both, $x_{\ell-1}$ is the stream entering, $F_\ell$ is the sublayer's computation, and Norm is LayerNorm or RMSNorm.

The difference is what happens to the identity path from the [residual stream](#the-residual-stream) section. In post-norm every normalization sits on that path, so a gradient travelling from the top to block 1 passes through 64 rescalings, and [Xiong et al.](https://arxiv.org/abs/2002.04745) showed that at the start of training the gradients near the output are much larger than those near the input. Post-norm stacks therefore need **warmup**, a schedule that starts the step size near zero and raises it over the first few thousand steps, and deep post-norm stacks still diverge easily. Pre-norm keeps the identity path free of any operation, so the 1 from the [residual stream](#the-residual-stream) section reaches every block, and deep stacks train stably without the long [warmup](/tutorials/llm-fundamentals/pretraining-at-scale/#learning-rate-schedules) post-norm needs, though large runs still use a short one. Pre-norm has its own cost. The stream is never rescaled, so it grows. If the embedding has a root mean square of 1 and each of 32 blocks adds a contribution of size 1 that is roughly unrelated to the others, the squared sizes add and the final stream has size about $\sqrt{1 + 32} \approx 5.7$. A late block's write then changes the stream's direction by about one part in 5.7, which is one reason late layers in pre-norm models often contribute less, and it is why pre-norm models add a final normalization before the output head. Some recipes add extra norms or rescale the residual branches to recover late-layer influence, and those are refinements on a pre-norm base.

## The feed-forward network

Attention mixes information across tokens, but something also has to compute on what each token has gathered. The feed-forward network, or FFN, does that computation: a small two-layer network applied to each token's vector separately, with the same weights for every position. It widens the vector, applies a nonlinear function to each number, and narrows it back:

$$
\operatorname{FFN}(x) = \phi(x W_1)\, W_2.
$$

Here $x$ is the normalized stream for one token as a row of $d$ numbers, $W_1$ is a $d \times d_{\text{ff}}$ matrix that widens it, $\phi$ is the **activation function** applied to every number separately, and $W_2$ is a $d_{\text{ff}} \times d$ matrix that narrows it back. The **hidden width** $d_{\text{ff}}$ is the number of hidden units, classically $4d$. A matrix of shape $d \times d_{\text{ff}}$ holds $d \cdot d_{\text{ff}}$ parameters, so the classic FFN holds $2 \cdot d \cdot 4d = 8d^2$, which at $d = 4{,}096$ is 134,217,728, twice the $4d^2$ of attention. Two thirds of a block's parameters therefore sit in the part that never looks at another token.

The activation is what makes the network more than one matrix, because two matrices in a row with nothing between them collapse into a single matrix. **ReLU**, the rectified linear unit, returns the larger of its input and zero. **GELU**, the Gaussian error linear unit from [Hendrycks and Gimpel](https://arxiv.org/abs/1606.08415), returns $u\,\Phi(u)$ for an input $u$, where $\Phi(u)$ is the probability that a standard normal value falls below $u$, so it behaves like ReLU for large inputs and lets small negative inputs through as small negative outputs. GPT-2 and BERT use GELU.

## Gated activations and SwiGLU

A plain activation decides how much of each hidden unit passes based only on that unit's own value. A gate lets a second learned signal, computed from the same input, make that decision instead. A **gated linear unit**, from [Dauphin et al.](https://arxiv.org/abs/1612.08083), computes two projections of the input and multiplies them, one acting as the gate and the other as the value. **SiLU**, the sigmoid linear unit, is $\operatorname{SiLU}(u) = u \cdot \frac{1}{1 + e^{-u}}$, a smooth curve close to GELU. **SwiGLU** uses SiLU on the gate branch, as proposed by [Shazeer](https://arxiv.org/abs/2002.05202):

$$
\operatorname{FFN}_{\text{SwiGLU}}(x) = \big(\operatorname{SiLU}(x W_{\text{gate}}) \odot x W_{\text{up}}\big)\, W_{\text{down}}.
$$

Here $W_{\text{gate}}$ and $W_{\text{up}}$ are both $d \times d_{\text{ff}}$ and produce the gate and the value, $\odot$ multiplies them coordinate by coordinate, and $W_{\text{down}}$ is $d_{\text{ff}} \times d$ and narrows the result back to width $d$. For a token whose gate pre-activations are $(2, -1)$ and whose values are $(3, 4)$, SiLU gives $2 \times 0.881 = 1.762$ and $-1 \times 0.269 = -0.269$, so the gated hidden vector is $(1.762 \times 3, -0.269 \times 4) = (5.285, -1.076)$. The first unit passes its value scaled up by 1.76, while the second shrinks its value to about a quarter and flips its sign, and the gate learned to make each call from the input.

Three matrices instead of two would raise the feed-forward network's (FFN's) parameters by half at the same hidden width, so the width is cut to keep the count near the classic $8d^2$. Setting $3 \cdot d \cdot d_{\text{ff}} = 8d^2$ gives $d_{\text{ff}} = \tfrac{8}{3}d$, which is the source of the $\tfrac{2}{3} \times 4d$ rule. For $d = 4{,}096$ that is $10{,}922.7$, and Llama rounds up to the next multiple of 256 so the matrices split evenly across hardware tiles, giving $43 \times 256 = 11{,}008$. The SwiGLU FFN then holds $3 \times 4{,}096 \times 11{,}008 = 135{,}266{,}304$ parameters, 0.8% above $8d^2 = 134{,}217{,}728$. Shazeer's experiments found the gated variants beat ReLU and GELU at matched parameters and compute, and PaLM, Llama, and Mistral all adopted SwiGLU. The paper offers no theory for why, so the usual explanation that multiplicative gates let a unit switch on context is a plausible reading rather than a proof.

## The decoder block

The sections from [residual stream](#the-residual-stream) to [gated activations and SwiGLU](#gated-activations-and-swiglu) supply every part of a block, so assembling one is mostly a matter of putting them in the right order. A **decoder block** is the repeating unit of a text generator: a pre-norm attention sublayer followed by a pre-norm SwiGLU sublayer, each wrapped in a residual connection. For the attention sublayer it is enough here to know that multi-head attention splits the width into $h$ heads of width $d_h$, and each head scores every earlier token, turns the scores into weights that sum to 1, and returns a weighted average of their information. The causal mask that makes it look only backward, and positional information, are developed in [Attention](/tutorials/llm-fundamentals/attention-and-positional-information/). One block then computes

$$
a = x + \operatorname{Attn}(\operatorname{RMSNorm}_1(x)), \qquad x' = a + \operatorname{FFN}_{\text{SwiGLU}}(\operatorname{RMSNorm}_2(a)).
$$

Here $x$ is the stream entering the block, $a$ is the stream after the attention sublayer has added its output, and $x'$ is the stream leaving. Each RMSNorm has its own gain. The reference 7B stacks 32 identical copies, each with its own weights, and the input and output of every block are vectors of $d = 4{,}096$ numbers per token.

![Decoder block](/images/llm-fundamentals/15d-decoder-block.png)

The diagram shows why the two sublayers do different jobs. Attention is the only place tokens exchange information, so a block without it would process each word in isolation. The feed-forward network (FFN) is where most of the per-token computation and most of the parameters sit. Width stays at 4,096 on every edge of the identity path, which is what lets blocks be stacked, removed, or inspected one at a time. Llama 2 uses exactly this block, and the full list of later variants such as grouped-query attention and different position schemes is in Modern LLM Architectures.

## The output head

After the last block, the model has one 4,096-number vector per position and needs a probability for every possible next token. The **output head** is one matrix $W_{\text{out}}$ of shape $d \times V$ that turns the final normalized vector into one score per vocabulary entry. Each score is a **logit**, an unnormalized number where higher means more likely. **Softmax** then exponentiates every logit and divides by the total, producing probabilities that are positive and sum to 1:

$$
z = \operatorname{RMSNorm}(x_L)\, W_{\text{out}}, \qquad P(\text{token } j) = \frac{e^{z_j}}{\sum_{i=1}^{V} e^{z_i}}.
$$

Here $x_L$ is the stream after the last block, $z$ is the row of $V$ logits, $z_j$ is the logit for token $j$, and the sum runs over the whole vocabulary of $V = 32{,}000$ tokens. A toy case has a three-token vocabulary of "cat", "dog", and "the", a final normalized vector $(1, 2)$, and output columns $(0, 1)$, $(0.6, 0.2)$, and $(0.1, 0)$. The logits are $0 + 2 = 2.0$, $0.6 + 0.4 = 1.0$, and $0.1$. Exponentials are 7.389, 2.718, and 1.105, which sum to 11.212, so the probabilities are 0.659, 0.242, and 0.099. If the true next token is "cat", the training loss for this position is $-\ln 0.659 = 0.417$, and [Language Modeling](/tutorials/llm-fundamentals/language-modeling-and-next-token-prediction/) develops that cross-entropy loss and the softmax in full.

**Weight tying** reuses the embedding table as the output matrix, since both map between tokens and $d$-number vectors. It saves $V \times d$ parameters, which is 131,072,000 in the reference 7B, only 1.9% of the model, and Llama 2 keeps them separate. In GPT-2 small, with $V = 50{,}257$ and $d = 768$, the same table is 38.6 million of about 124 million parameters, roughly 31%, which is why small models usually tie. The head's arithmetic is $2 \times 4{,}096 \times 32{,}000 = 262$ million operations per token, under 2% of the forward pass computed in the [FLOPs per token](#flops-per-token) section.

## Parameter counting

Counting parameters is bookkeeping over matrix shapes. A matrix with 4,096 rows and 11,008 columns holds their product, 45,088,768 numbers, and the model's total is the sum over every matrix and every normalization gain. The reference 7B, with $L = 32$ blocks, width $d = 4{,}096$, vocabulary $V = 32{,}000$, and SwiGLU hidden width $d_{\text{ff}} = 11{,}008$, counts as follows.

1. Input embedding, one row per vocabulary entry: $32{,}000 \times 4{,}096 = 131{,}072{,}000$.
2. Attention in one block, four $d \times d$ matrices for queries, keys, values, and output: $4 \times 4{,}096^2 = 67{,}108{,}864$.
3. SwiGLU FFN in one block, three matrices of $d \times d_{\text{ff}}$: $3 \times 4{,}096 \times 11{,}008 = 135{,}266{,}304$.
4. Two RMSNorm gains in one block: $2 \times 4{,}096 = 8{,}192$. One block totals $202{,}383{,}360$.
5. All 32 blocks come to $32 \times 202{,}383{,}360 = 6{,}476{,}267{,}520$, the final RMSNorm adds 4,096, and the untied output head adds another 131,072,000.
6. Add the four parts:

   $$
   131{,}072{,}000 + 6{,}476{,}267{,}520 + 4{,}096 + 131{,}072{,}000 = 6{,}738{,}415{,}616.
   $$

   That is about 6.74 billion. At 2 bytes per number in [bf16](/tutorials/llm-fundamentals/pretraining-at-scale/#mixed-precision-with-bf16), a 16-bit number format, the weights take 13.48 GB, or 12.55 GiB in binary gigabytes of $2^{30}$ bytes.

![Parameter breakdown](/images/llm-fundamentals/15d-parameter-breakdown.png)

A quick estimate drops embeddings and norms and uses $4d^2$ for attention plus $8d^2$ for the feed-forward network (FFN), giving $N \approx 12 L d^2$. For the reference model that is $12 \times 32 \times 4{,}096^2 = 6{,}442{,}450{,}944$, about 4.4% below the exact count. Of that 296 million gap, 262 million is the two embedding tables, 33.6 million is SwiGLU's rounding from 10,922.7 to 11,008, and the norms add the last 0.27 million. The estimate works well for large models and badly for small ones, where embeddings are a big share, as the GPT-2 small example in the [output head](#the-output-head) section showed. Two common changes break the $4d^2$ attention term. Grouped-query attention, where groups of query heads share one key head and one value head, shrinks the key and value matrices with 8 such groups to $d \times 1{,}024$ each, and a mixture of experts multiplies the FFN term, as the [mixture of experts](#mixture-of-experts) section shows.

## FLOPs per token

Parameter count says how much memory the weights need, and a separate count says how much arithmetic each token costs. A **FLOP**, or floating-point operation, is one addition or multiplication on a decimal number. Multiplying a token's vector by a $d \times d$ matrix takes $d^2$ multiplications and about $d^2$ additions, so every weight is used for about 2 FLOPs per token. The **forward pass**, computing the output from the input, therefore costs about $2N$ FLOPs per token, where $N$ is the parameter count. For the reference 7B that is $2 \times 6.74 \times 10^9 = 13.5$ GFLOPs, where one GFLOP is a billion FLOPs.

The **backward pass** computes gradients and costs about twice the forward pass. For each matrix multiplication it needs two more of the same size, one giving the gradient for the layer's input so the signal can continue to earlier layers and one giving the gradient for the weights so they can be updated. Training per token is therefore $2N + 4N = 6N$, which is 40.4 GFLOPs per token for the reference model. Over a training run of $D$ tokens this becomes the $6ND$ rule, $8.09 \times 10^{22}$ FLOPs for 2 trillion tokens, which [Pretraining](/tutorials/llm-fundamentals/pretraining-at-scale/) turns into days on graphics processors. Recomputing intermediate results during the backward pass instead of storing them, which saves memory, adds roughly one more forward pass, about $8N$, so real runs often count more.

The $2N$ rule leaves out attention's own arithmetic, which has no weights. A token at position $t$ compares its query with $t$ keys and averages $t$ values, about $4td$ FLOPs per block across all heads. Averaged over a causal sequence of **context length** $n$, the number of tokens the model reads at once, this adds about $2Lnd$ per token. At $n = 4{,}096$ that is $2 \times 32 \times 4{,}096 \times 4{,}096 = 1.07$ GFLOPs, 7.4% of the forward pass. The two terms are equal when $n = N/(Ld) \approx 51{,}400$ tokens, so for this shape the weights dominate until contexts get long, and attention then grows linearly per token while the weight term stays fixed.

FLOPs set the cost of training and of processing a long prompt, but generating one token at a time is usually limited by reading the 13.48 GB of weights from memory instead, which [Inference](/tutorials/llm-fundamentals/inference-and-decoding/) works through.

## Mixture of experts

A dense model runs every parameter for every token, so making it know more also makes every token cost more. A **mixture of experts**, or MoE, breaks that link by running only part of the feed-forward network (FFN) for each token, following [Shazeer et al.](https://arxiv.org/abs/1701.06538) and [Switch Transformer](https://arxiv.org/abs/2101.03961). Each MoE layer keeps $E$ separate FFNs, each called an **expert**, and a **router**, a small learned $d \times E$ matrix, scores the experts for each token. **Top-k routing** keeps the $k$ highest-scoring experts, renormalizes their router probabilities $p_e$ to sum to 1 (as Mixtral does; some models skip this step), and returns the weighted sum of their outputs. Attention, norms, and embeddings stay shared.

Left alone this imbalance worsens, because a busier expert trains faster and attracts still more tokens, until a few experts take everything. A **load balancing loss**, an extra training penalty that grows when assignments are uneven, keeps the experts in use, and Advanced Topics derives it along with the capacity limits that drop overflow tokens.

The payoff and the cost show up in two counts. **Total parameters** are every weight stored, which sets memory. **Active parameters** are the weights one token actually multiplies against, which sets FLOPs. A concrete case swaps the reference 7B's FFN for 8 SwiGLU experts of the same size, routed top-2. Each expert holds 135,266,304 parameters, and the router adds $4{,}096 \times 8 = 32{,}768$ per block. Total parameters become 37.04 billion, which is 74.1 GB in bf16, while active parameters are 11.07 billion, so each token costs about $2 \times 11.07 = 22.1$ GFLOPs forward. The model stores 5.5 times the dense model's weights for 1.6 times its arithmetic. Mixtral 8x7B, from [Jiang et al.](https://arxiv.org/abs/2401.04088), has 46.7 billion total and 12.9 billion active, and Modern LLM Architectures covers how much quality the extra storage actually buys, which is less than the storage ratio.

## Architecture families and training objectives

The same blocks can be wired three ways, and the wiring decides what the model can be trained to do. Each family pairs an attention pattern with an objective, the prediction task whose error training minimizes. An **encoder-only** model such as [BERT](https://arxiv.org/abs/1810.04805) lets every token see every other token and trains with **masked language modeling**, hiding about 15% of tokens and predicting them. A decoder-only model such as GPT or Llama uses a [causal mask](/tutorials/llm-fundamentals/attention-and-positional-information/#the-causal-mask) so each token sees only earlier ones, and trains with **causal language modeling**, predicting the next token at every position. An **encoder-decoder** model such as [T5](https://arxiv.org/abs/1910.10683) reads a source with a bidirectional encoder and writes the output with a causal decoder that also uses **cross attention**, attention whose queries come from the output and whose keys and values come from the encoded source. T5 trains with **span corruption**, replacing random runs of tokens with placeholder markers and generating the missing runs. A **prefix LM**, or prefix language model, is a decoder-only model whose first part, the prefix, is read bidirectionally while the rest is generated causally.

The objectives differ sharply in how much signal one sequence gives. In a 512-token sequence, masked modeling yields about $0.15 \times 512 \approx 77$ predictions, while causal modeling yields about 512, one per position. T5's span corruption with spans averaging 3 tokens yields the same 77 hidden tokens in about 26 spans. Decoder-only models came to dominate general-purpose large language models for four connected reasons. They extract a learning signal from every token. One objective serves every task through prompting, since any task can be written as text to continue. Generation streams naturally one token at a time while reusing stored results for earlier tokens. With a single stack there are fewer design choices to scale. [Wang et al.](https://arxiv.org/abs/2204.05832) found causal decoders best for zero-shot use, meaning tasks given without examples, after plain pretraining on raw text, while models that read their input bidirectionally and train with masked modeling, such as encoder-decoders, did better after multitask fine-tuning, meaning further training on many labeled tasks, so the win is about the general-purpose use case rather than every task.

| Situation | Choice | Main qualification |
|---|---|---|
| General assistant, open-ended generation, prompting with a few examples | Dense decoder-only | Cost per token grows with every parameter |
| Embeddings, retrieval, or classification at low latency | Encoder-only | Cannot generate text |
| Fixed input mapped to a different output, such as translation or speech | Encoder-decoder | Two stacks to scale and serve |
| Quality per FLOP matters and memory across many graphics processors is available | Decoder-only mixture of experts | Memory follows total parameters and needs load balancing |
| One graphics processor or an edge device with tight memory | Small dense decoder-only | Lower ceiling on quality |

At staff level the choice between a dense model and a mixture of experts gets decided by an experiment with a stated exit. The experiment fixes a training budget in FLOPs, trains both at that budget on the same data, and compares quality alongside serving cost per million tokens at the expected batch size. A good decision record writes the reversal condition down before the run, for instance that the dense model ships if serving memory or the communication between graphics processors holding different experts makes the mixture's cost per token higher at equal quality.
